# 近期外部方法适配验收（测试推理前冻结）

## 名单与依据

本轮正式名单为 **FedCLASS、Re-Fed、AF-FCL**，不根据测试胜负删选。已有 DER++、Fed-LwF 不计入新增方法数。全部为“统一流量表示下的外部策略适配比较”，不声称复现原图像论文分数。三个任务均从随机初始化完整执行，不共享 M0 的 Task 1。

| 候选 | 核查结果 | 本轮决定 |
|---|---|---|
| FedCBDR (NeurIPS 2025) | 已冻结团队仓库。README要求 method=C，main.py无C分支，多个顶层导入指向缺失文件。B.py有温度损失及FLDataSelector，但采用各客户端分别SVD后拼分数，而论文要求服务器对全局拼接伪特征SVD；缓存配额/全局采样与论文也不能直接确认等价。 | 暂不作为完整FedCBDR运行；不把B.py或本地配额ER冒充完整方法。 |
| FedCLASS (2024预印本，2025期刊) | 作者仓库具备增广自蒸馏、前阶段全局教师、首记录类别缓存和FedAvg流程。 | 纳入；保留核心损失的温度、KL方向、目标中的学生梯度路径。 |
| FedSSI (ICML 2025) | 已核对论文PSM及重要性公式、作者主页与公开基准NCCL；未发现FedSSI执行代码。算法的PSM迭代、SI贡献离散化及具体状态更新仍需独立约定才能执行，当前不冒充已核实复现。 | 按用户允许的备选路线以AF-FCL替补；不以普通SI/EWC改名。并不据此断言作者代码不存在。 |
| Re-Fed (CVPR 2024) | 找到作者相关NCCL基准，包含clientrefed/trainer_classification_ReFed。该版本有arg/args错误、把批次分数当样本分数、更新后重用旧计算图等问题，不能直接执行即称复现。论文HTML Eqs3–6给出完整PIM及样本重要性定义。 | 纳入论文依据的明确适配：PIM近端更新、全参数逐样本梯度平方范数、递减权重和top-k保留全部保留；记录下述mini-batch与存储约定。 |
| AF-FCL (ICLR 2024) | 作者仓库含条件仿射normalizing flow、历史flow生成、自适应概率加权、历史/全局教师和模型/flow聚合。 | 纳入；直接抽取并执行作者核心方法。四层flow、hidden512保留，96维输入为共享紧凑特征维度。 |

仓库commit与逐文件SHA见 official_sources.json，原始代码只读保存在official/。vendor/nflows仅把两个与实际仿射flow无关的UMNN导入改为可选，使用的仿射变换并未修改。

## 共同接口与限制

沿用三组既有诊断数据、客户端、三个任务、输入归一化、样本ID和训练/验证/测试人口。采用原width48双分支、SE、融合归一化、Adapter构成共同特征提取器。外部方法使用线性头；AF-FCL保留其额外fc2。未强制加入CosFace训练间隔，因此这是完整策略比较，不是单因素消融。M0自身实现不变，复用原结果。

全局词表固定，但旧类和新类从**过去/当前训练标签**集合定义，不要求类别编号连续。USTC Task3及DoH后续任务没有全局新类，作为类别再现阶段保留，FedCLASS此时退化到旧类蒸馏而不是伪造新类。固定头仍对完整词表输出；FedCLASS增广蒸馏在已见类子空间计算。没有测试标签参与训练定义。所有方法推理只需统一分类器，不使用任务ID或服务器原始数据。

## FedCLASS执行映射

- 当前数据与每客户端最多240条历史样本合并，均匀shuffle，每轮3个本地epoch；不强加M0的独立0.5回放损失。
- 保存前阶段终点全局模型为冻结教师，下一阶段第一次既有模型下行即可获得，不另加一次教师传输。
- CE在完整显式类别头上计算。KD以作者ours.py为依据：T_old=5、T_new=3；学生p，旧教师q；新类分数从学生导出，旧类目标q乘剩余质量。
- 原代码target=Z保留学生梯度，new部分来自T_old学生分布；本适配保留，不擅自detach/归一化或加入T²。KD是学生相对增广目标的reverse-KL式目标（包含原clip与epsilon）。
- 作者首记录类缓存推广到类别再现：旧缓存与当前样本合并，按本地已见类等分容量，每类保留最先出现记录，防止重复增加同类配额导致超容量。该约定与M0近期保留不同。
- 参数候选为lr∈{原共同lr,0.01}×alpha∈{1,5,10}，T固定作者配置5/3；SGD momentum0.9, weight_decay1e-5。每数据集单独用seed42验证选择。

## Re-Fed执行映射

- 核心保留PIM、全局近端锚、全参数逐样本梯度重要性与高分样本选择，分类模型以当前+缓存合并CE训练。
- 任务结束、当前数据尚未过期时进行选择，候选仅为旧缓存+当前原始记录。PIM从本轮终点本地模型出发，全局锚为本阶段终点全局模型；该必要锚下行计费。
- PIM执行3个冻结顺序mini-batch pass，q=(1−lambda)/(2lambda)，SGD；为mini-batch适配明确采用每pass 1/p权重，在该pass样本被访问时记录实际全参数梯度平方范数，不是批次梯度或最后一层近似。
- 作者论文定义总本地可用样本预算，本轮将240限制到历史缓存（当前任务完整数据仍可用），以匹配用户规定；此资源协议变化必须在论文中披露，不能称原协议逐项复现。
- 每阶段选择top240，按候选顺序打破分数平手。保存全部候选分数、标签与选择索引。临时PIM可丢弃，不把其瞬时内存写成持久缓存；重要性梯度计算次数单列。
- lr∈{原共同lr,0.01}×lambda∈{0.2,0.5,0.8}，6个完整验证配置/数据集。分类器Adam，PIM SGD；本地轮次按用户共同设置固定。

## AF-FCL执行映射

- 作者PreciseModel中的flow工厂、flow训练、flow采样、样本可信度、分类器训练及历史/全局双教师损失通过AST抽取，避免图像包导入；实际方法体不改写。
- 流量融合特征96维，条件类别维度随固定词表为4/5/6，四层仿射耦合与hidden512保留。额外fc2与分类头保留作者接口。
- 每当前批次先更新flow：当前特征似然+历史flow生成特征似然；然后执行概率加权生成回放的fc2更新，再执行当前分类+历史和全局特征/输出蒸馏。
- classifier和flow每轮均上传下载并聚合；新阶段教师/历史flow从既有第一轮下行复制。没有原始历史输入缓存，但保留教师和flow，存储与辅助优化器更新均单列。
- 三个冻结参数包：(lr=共同lr,flow_weight0.1)、(lr=.001,flow_weight0.1)、(lr=.001,flow_weight1)。其他系数见plan.json；lr允许验证调整，不以测试调参。
- 共同预算按全部flow传输核算。若最小1/1/1超37,208,796字节，如实报告不可行，不压缩/删除flow伪造可比结果。

## AF-FCL验证阶段数值修正

未加稳定保护的作者核心在Task2产生非有限分类器权重，该失败完整保存在development_preflight_AF_native_v1，未测试。冻结修正：可信度高斯密度的局部类别方差下限1e-6，分类器/生成回放head/flow优化步前梯度范数裁剪10，并在梯度非有限时立即报错。该修改影响数值更新，故正式名称明确为带稳定性保护的AF-FCL适配，不称逐行未修改复现；未删除flow、可信度加权、历史生成回放或双教师。

出版信息补充：AF-FCL原论文出版页 https://proceedings.iclr.cc/paper_files/paper/2024/hash/dd1810bba6fd3d8b7a6f4aa7c263c591-Abstract-Conference.html ；三篇BibTeX见external_methods.bib。

## 优化器执行约定

实际适配代码中，所有方法每次客户端训练调用均新建优化器，主轮次间不恢复动量/Adam矩；AF-FCL作者用户对象原本可保持优化器状态，因此这里属于统一执行环境下的额外适配差异，不能声称优化器轨迹与作者实现相同。流/教师权重及历史flow等核心知识状态照常跨阶段保留。该事实由冻结代码直接核查，补记在此，未修改正在运行的训练。

## 原生AF蒸馏呈现量的汇总口径

原始client_records中的distillation_presentations计数器仅在自定义FedCLASS分支递增，AF原生函数内部未接入该计数器；原始零值不能解释为AF没有蒸馏。最终汇总从实际批次规模重建：AF每批对当前输入和生成特征各执行一次KD，二者样本量相等；另按是否有历史教师分别记录教师样本呈现量。flow对当前输入的呈现次数也单列。该转换仅在报告层执行，原始日志不改写。

## 实质聚合错误修复及作废记录（正式测试前）

新适配初版误将flow置换/索引缓冲区作为浮点参数FedAvg。实际阶段2检查点出现96个索引仅剩94或93个唯一值，破坏可逆性。修复为仅对named_parameters聚合，所有缓冲区必须与服务器完全一致并直接复制；每轮校验置换为0..95的双射。全部9个受影响AF候选尝试，无论是否完整或分数高低，移至invalidated_flow_aggregation_v1，均不进入选择与结果表。此前AF数值失败或低分不能解释为方法性质。保留未受影响的FedCLASS/Re-Fed验证运行，其训练路径未改变。旧代码完整保存于code_before_flow_buffer_fix。

## Re-Fed通信口径边界

本实现任务结束进行PIM选择并获取全局锚，随后仍按统一逐轮完整下行规则开始下一任务；原方法若在新任务开始选择并复用同一次全局下行，可避免边界重复发送。终点缓存准备也可能在已知序列结束时省略。因此最终主表报告本执行的真实序列化核算，同时单列上述两种会计敏感性，不将额外锚下行称为框架不可避免的通信开销。该分析不改模型权重或已冻结的验证选择，优化传输后的运行本轮未另行实测。
